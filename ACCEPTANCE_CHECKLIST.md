# Чек-лист приёмки — Jitsi Recording Bot

Заполняется при проверке на целевом сервере `meet.it-expertise.ru`.
Отметь `[x]` при пройденном пункте; «примечание» — если есть оговорки.

Перед прогоном:
- [ ] Docker Desktop запущен
- [ ] `make build` собрал образ без ошибок
- [ ] `make up` поднял контейнер; `make ps` показывает running
- [ ] `http://127.0.0.1:8080` открылась панель
- [ ] Подготовлена тестовая встреча: 2 участника, один говорит, один делает демонстрацию экрана с читаемым текстом

## Критерии (14)

| # | Критерий | Как проверяем | Результат |
|---|---|---|---|
| 1 | Запуск одной кнопкой по вставленной ссылке | Вставить ссылку → «Подключиться и записывать» | ☐ примечание: |
| 2 | Авто-вход под заданным именем без действий в браузере | Указать имя бота → бот сам проходит prejoin и входит | ☐ примечание: |
| 3 | Камера и микрофон бота выключены | В встрече проверить карточку бота (cam/mic off, не отправляет поток) | ☐ примечание: |
| 4 | 10-мин тестовая встреча записана с видео и слышимым звуком 2 участников | Дождаться/остановить; открыть MP4, проверить звук обоих | ☐ примечание: |
| 5 | Демонстрация экрана в записи, контрольный текст читается | На демо показать текст → в записи текст читается | ☐ примечание: |
| 6 | Физический мик и звук стороннего приложения НЕ в записи | Во время записи поговорить в мик хоста + включить сторонний звук → в записи их нет | ☐ примечание: |
| 7 | Закрытие вкладки панели не прерывает запись | Закрыть браузер/вкладку → запись продолжается | ☐ примечание: |
| 8 | Ручная остановка и ограничение длительности работают | (а) «Остановить запись и выйти»; (б) задать малый лимит → авто-стоп | ☐ примечание: |
| 9 | MP4 открывается, есть видео- и аудио, перемотка | Открыть в плеере, перемотать | ☐ примечание: |
| 10 | Рассинхрон звука/видео ≤ 500 мс | Встречный тест: хлопок/отметка времени → оценить сдвиг | ☐ примечание: |
| 11 | Вторая одновременная запись не запускается | Во время активной записи попытаться запустить новую → отказ | ☐ примечание: |
| 12 | После перезапуска история и готовые файлы сохраняются | `make restart` → история на месте, файлы на месте | ☐ примечание: |
| 13 | При принудительном завершении браузера — ошибка + промежуточная запись не удалена | Убить браузер/контейнер резко → статус failed, файл/файл сохранён | ☐ примечание: |
| 14 | После завершения не остаются фоновые процессы | `make logs`, проверка процессов/портов после стоп | ☐ примечание: |

## Чек-лист файлов после задачи

- [ ] `recordings/<папка>/recording.mp4` существует
- [ ] `recordings/<папка>/metadata.json` существует и заполнен
- [ ] `recordings/<папка>/session.log` содержит id задания и детали (без секретов из ссылок)
- [ ] Промежуточный `recording.mkv` удалён после успешной проверки (для completed)
- [ ] В истории в панели запись со статусом `completed` и ссылкой «Скачать»

## Типовые проблемы и что смотреть

| Симптом | Куда смотреть |
|---|---|
| Бот не входит, статус `failed` | `session.log`, `app/jitsi/join.py` (селекторы prejoin) |
| Нет звука в записи | `docker/entrypoint.sh` (sink `botsink`), `app/capture/audio.py`, `make logs` |
| Нет видео / чёрный экран | Xvfb `:99`, `--start-fullscreen`, `app/jitsi/browser.py` |
| Встреча не поднимает потоки (WebRTC) | корп-сеть/UDP → нужен TURN |
| Рассинхрон | один ffmpeg-процесс? (`app/capture/recorder.py`) |
