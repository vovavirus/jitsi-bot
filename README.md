# Jitsi Recording Bot

Локальное приложение-бот, которое подключается к открытой встрече Jitsi как
отдельный участник, записывает изображение и звук встречи и сохраняет результат
локально. Управление — через веб-панель на `http://127.0.0.1:8080`.

Поддерживает **несколько одновременных записей** (по умолчанию до 3, настраивается
`max_concurrent_recordings`). У каждой записи изолированные ресурсы: свой
X-дисплей, свой PulseAudio-инстанс и свой аудио-sink, поэтому запись и звук
встреч не пересекаются.

Весь бот работает внутри **Linux-контейнера** (Docker Desktop на macOS). В
контейнере: Python/FastAPI + Playwright/Chromium + Xvfb (виртуальный экран) +
PulseAudio (изолированный аудиовыход) + FFmpeg + SQLite. Панель пробрасывается
на macOS-хост только на `127.0.0.1:8080`.

---

## Возможности

- Подключение к открытой встрече Jitsi под заданным именем (автоматический
  прохождение prejoin-экрана).
- Собственная камера и микрофон бота **не запрашиваются** и **не отправляются**.
- Запись только окна встречи (виртуальный экран 1920×1080, 25 fps), не рабочего
  стола и не чужих окон.
- Изолированная запись смешанного звука встречи (без физического микрофона и без
  звука других приложений машины).
- Итог: MP4 (H.264 + AAC), перемотка, отдельная папка на запись с метаданными и
  журналом.
- Веб-панель: запуск, статус активной записи, остановка/отмена, история, скачивание.
- Несколько встреч одновременно: до `max_concurrent_recordings` параллельных
  записей, каждая в своём изолированном окружении (X-дисплей + PulseAudio).
- Запланированное начало: бот может подключиться к встрече к указанному времени.
- Лимит длительности, проверка места на диске, защита от переполнения слотов.
- История и готовые файлы переживают перезапуск; аварийное завершение помечает
  задание как прерванное.

## Требования

- macOS (Apple Silicon, arm64; amd64 — через Rosetta).
- **Docker Desktop** (запущен).
- Доступ к серверу Jitsi (`https://meet.it-expertise.ru`) из сети машины.

> Приложение не требует прав root на хосте. Весь привилегированный по своей
> природе функционал (Xvfb, PulseAudio, Chromium) изолирован внутри контейнера,
> где выполняется от непривилегированного пользователя образа (uid 1000).

## Установка и запуск

```bash
# 1. Перейти в каталог проекта
cd jitsi-meet-bot

# 2. (необязательно) создать конфигурацию
cp config.example.yaml config.yaml
#    при необходимости закомментировать в docker/docker-compose.yml строку:
#    - ../config.yaml:/app/config.yaml:ro

# 3. Собрать и запустить
make build
make up

# 4. Открыть панель
open http://127.0.0.1:8080
```

Управление:

```bash
make logs     # логи контейнера
make ps       # статус
make restart  # перезапуск
make down     # остановка
```

Альтернатива без Make:

```bash
docker compose -f docker/docker-compose.yml up --build -d
```

Первый запуск дольше — Docker скачивает образ и зависимости. После `make up`
панель доступна по `http://127.0.0.1:8080`.

## Пользовательская инструкция

1. Откройте `http://127.0.0.1:8080`.
2. Вставьте ссылку на встречу, например
   `https://meet.it-expertise.ru/название-комнаты`.
3. При желании поменяйте название записи, имя бота (по умолчанию
   «Владимир Русин AI») и максимальную длительность (по умолчанию 180 минут).
4. (необязательно) Укажите **«Начало встречи»** — дату и время подключения.
   Если поле пустое, бот подключится сразу. Если указано время, бот будет
   ждать и подключится к этому времени (по часовому поясу вашего браузера).
   Пока идёт ожидание, карточка показывает состояние «Запланировано», и
   встречу можно отменить.
   > Важно: если контейнер перезапустят до времени начала, запланированная
   > встреча будет помечена «Прервано» — её нужно будет добавить заново.
5. Нажмите **«Подключиться и записывать»** (или «Запланировать и записывать»).
   - Бот открывает встречу, вводит имя, нажимает «Присоединиться» и входит.
   - Камера и микрофон бота выключены.
6. В карточке «Активная запись» видно состояние, время начала, длительность и
   текущий размер файла.
   - **«Остановить запись и выйти»** — штатная остановка и финализация MP4.
   - **«Отменить подключение»** — доступен, пока бот ещё не вошёл.
   - **«Отменить запланированную встречу»** — доступен, пока идёт ожидание.
7. Закрытие вкладки панели запись **не** останавливает — бот продолжает работать
   в фоне, пока контейнер запущен.
8. После завершения в карточке и в «Истории записей» появляется готовый MP4:
   можно скачать, увидеть путь и длительность.

## Конфигурация

Параметры задаются в `config.yaml` (см. `config.example.yaml`) и/или
переменными окружения в `docker/docker-compose.yml`:

| Параметр | Значение по умолчанию | Описание |
|---|---|---|
| `storage_dir` | `/app/recordings` | Каталог хранения в контейнере (проброшен в `./recordings`) |
| `min_free_space_gb` | `2` | Порог свободного места (ГБ) |
| `connect_timeout_s` | `120` | Тайм-аут входа во встречу |
| `default_max_duration_min` | `180` | Макс. длительность по умолчанию |
| `default_bot_name` | `Владимир Русин AI` | Имя бота по умолчанию |
| `video.width/height/fps` | `1920/1080/25` | Параметры записи |
| `audio.codec/bitrate` | `aac/128k` | Аудиокодек и битрейт |
| `pulse_sink` | `botsink` | Имя виртуального аудио-sink (слоты: `botsink`, `botsink1`, …) |
| `max_concurrent_recordings` | `3` | Сколько встреч записывать одновременно |
| `log_level` | `INFO` | Уровень логирования |

## Расположение файлов и журналов

На macOS-хосте (в корне проекта):

```
recordings/
├── .bot.sqlite                          # история и состояния заданий
└── 2026-10-29_220000_project-sync_a1b2c3/
    ├── recording.mp4                    # итоговая запись
    ├── metadata.json                    # метаданные задания
    └── session.log                      # технический журнал с id задания
```

- История хранится в `recordings/.bot.sqlite`.
- Каждый журнал `session.log` привязан к конкретному заданию и содержит
  технические детали (без секретов: в логах нет query-параметров ссылок).
- Логи приложения контейнера — `make logs`.

## Как это работает (архитектура)

| Компонент | Роль |
|---|---|
| Python + FastAPI | Панель, REST API, WebSocket-статусы |
| Playwright + Chromium | Открывает встречу, автоматизирует prejoin-вход |
| Xvfb | По виртуальному экрану 1920×1080 на каждую запись (:99, :100, …) |
| PulseAudio | По инстансу с изолированным аудио-sink на каждую запись (botsink, botsink1, …) |
| FFmpeg | Захват `x11grab` (видео) + `pulse` (аудио) → MKV → MP4 |
| SQLite | История и состояния |
| Файловая система | Видео, метаданные, журналы |

Пайплайн захвата — **один** процесс FFmpeg записывает видео и аудио
синхронно, что минимизирует рассинхрон. Временная запись — MKV (устойчиво к
крашу), затем remux в MP4 **без перекодирования** (`-c copy`).

Состояния задания:
`created → [scheduled →] connecting → recording → finalizing → completed`,
а также `failed / cancelled / interrupted`. Статус `scheduled` — бот ждёт
времени начала. Статус `completed` присваивается
только после проверки итогового MP4 (наличие видео- и аудиодорожек).

## Безопасность и эксплуатация

- Панель доступна только на `127.0.0.1` хоста (не публикуется в сеть).
- Веб-интерфейс не даёт доступ к произвольным файлам: скачивание разрешено только
  для файлов внутри каталога записей.
- В журналы не пишутся секретные параметры ссылок (лишь origin + путь комнаты).
- Используется одноразовый профиль браузера (новый на каждое задание).
- После завершения освобождаются процессы браузера, записи и виртуального окружения.
- При остановке приложения активная запись доводится до финализации.
- Сообщения об ошибках — на русском.

## Известные ограничения (MVP)

- Число одновременных записей ограничено `max_concurrent_recordings`
  (по умолчанию 3). Каждый слот занимает ~1 ядро CPU и ~1 ГБ RAM — на слабых
  машинах уменьшите лимит в `config.yaml` / `docker-compose.yml`.
- Совместимость входа проверена на конкретном сервере `meet.it-expertise.ru`
  (стандартный Jitsi Meet web-client). Универсальная поддержка всех версий/модов
  Jitsi не гарантируется; при смене сервера могут потребоваться правки селекторов
  в `app/jitsi/join.py`.
- Не поддерживается вход в закрытые/защищённые паролем встречи и обход
  ожидание-допуска — такие сценарии завершаются с понятной ошибкой.
- Нет облачного хранения, Telegram-управления, нескольких встреч, автопереподключения,
  расшифровки.
- Захват идёт с одного виртуального экрана: в записи — интерфейс встречи в текущей
  раскладке (видео участников, демонстрация экрана, переключения).

## Критерии приёмки — покрытие

> Для реальной проверки на сервере используй `ACCEPTANCE_CHECKLIST.md`
> (пошаговый чек-лист по всем 14 критериям + куда смотреть при сбоях).

| Критерий | Где обеспечивается |
|---|---|
| Запуск одной кнопкой, авто-вход под именем | `app/jitsi/join.py`, панель |
| Камера/микрофон бота выключены | `app/jitsi/browser.py` (media-permission не выдаются) |
| 10-мин запись с видео и звуком двух участников | `app/capture/recorder.py` |
| Демонстрация экрана в записи | захват всего окна встречи (`x11grab`) |
| Мик и сторонние приложения не в записи | изолированный PulseAudio-sink в контейнере |
| Закрытие панели не прерывает запись | бот — фоновый контейнер |
| Ручная остановка и лимит длительности | `app/core/orchestrator.py` |
| MP4 с дорожками, перемотка | remux `-c copy` + faststart, проверка `ffprobe` |
| Рассинхрон ≤ 500 мс | один ffmpeg-процесс для видео+аудио |
| Не более N одновременных записей | слоты ресурсов в оркестраторе |
| История и файлы после перезапуска | SQLite + каталог (volume) |
| Краш браузера → ошибка + материал сохранён | finalize с сохранением MKV/MP4 |
| Нет фоновых процессов после задания | cleanup в `finally` (браузер/ffmpeg) |

## Структура кода

```
app/
├── main.py                 # FastAPI, lifespan, graceful shutdown
├── config.py               # конфигурация (YAML + env)
├── api/
│   ├── routes.py           # REST API
│   └── ws.py               # WebSocket-статусы
├── core/
│   ├── models.py           # Task, состояния
│   ├── orchestrator.py     # жизненный цикл задания
│   └── events.py           # pub/sub для live-обновлений
├── jitsi/
│   ├── browser.py          # запуск Chromium (без cam/mic)
│   └── join.py             # prejoin-вход, подтверждение, ошибки
├── capture/
│   ├── video.py            # Xvfb
│   ├── audio.py            # PulseAudio sink
│   └── recorder.py         # FFmpeg: захват, finalize, проверка
├── storage/
│   ├── db.py               # SQLite (история/состояния)
│   └── files.py            # имена, санитизация, место на диске
└── static/index.html       # веб-панель
docker/
├── Dockerfile
├── docker-compose.yml
└── entrypoint.sh
```
